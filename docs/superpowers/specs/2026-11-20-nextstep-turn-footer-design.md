# NextStep 轮尾推荐设计

状态：首版已在工作区实现，扩展 API 为 `1.5.0`。协议见 [turnFooter schema](../../../packages/shared/src/extension-host/turnFooter.ts)；桌面端到端验收仍待完成，见 [覆盖矩阵](../../testing/plugin-management-lifecycle-e2e-coverage-matrix.md)。

## 目标和范围

NextStep 在一轮 AI 回答成功后，根据截至该回复的会话内容给出 2–4 条不同维度的推进建议。建议在复制、点赞等操作栏下方纵向排列，按概述（`label`）的 Unicode 码点数从短到长稳定排序，同长保留原顺序。用户可以点击建议继续当前会话，也可以手动刷新。自动生成最多一次；每次受理的手动刷新追加一个版本，不覆盖历史。再次打开聊天或切回会话时，只读取最新版本。

首版只支持 Desktop 本地工作区的主对话，只在当前分支最新一轮有资格的回复下显示。只启用一个轮尾提供者；首版不做多插件排序、历史版本浏览或批量补生成。不支持 Web、手机远控、远程工作区、辅助对话及只读会话。不开通任意 HTML 或全局样式注入，不把推荐写成聊天消息。

## 职责和接线

| 层                           | 负责                                                                                                                                          | 不负责                                               |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| CLI / 会话运行时             | 在实时 V4 投影提交后给出产品轮成功收口事实，按 transcript 消息映射解析最终回复的持久消息 ID；复用现有模型工厂、凭据和用量记录运行独立文本生成 | 推荐策略、版本历史、界面显示                         |
| Window Host / Extension Host | 注册并路由受限的轮尾提供者；绑定工作区、会话和最终回复；授权并限制独立生成；转发按锚点的更新通知                                              | NextStep 专用数据库、推荐提示词、版本号分配          |
| NextStep 插件                | 读取有权限的会话历史；构建提示词、筛选生成场景、校验模型结果；持久化自动认领、手动刷新和版本历史                                              | 直接访问宿主模型凭据、写会话数据库、自动发送用户消息 |
| Renderer                     | 在回复操作栏下渲染状态和按钮；读取最新结果、发出用户点击；复用现有会话发送和错误处理                                                          | 发起自动生成、维护持久缓存或第二套消息队列           |

复用 [扩展插槽目录](../../../packages/shared/src/extension-host/slots.ts)、[轮尾原生操作栏](../../../packages/ui/src/v4/ConversationTurnGroup.tsx)、[扩展会话读取能力](../../../packages/shared/src/extension-host/capabilities.ts)和 [CLI 独立模型执行](../../../apps/zcode-cli/packages/core/src/runtime/methods/sample-model.ts)。不复用依赖活页面令牌和页面取消生命周期的 MCP App 入口。先在现有 Extension Host 架构内接线，不新增独立宿主进程。

```text
CLI：实时 V4 提交 / 产品轮成功收口，按 transcript 消息映射解析最终回复锚点
  → Window Host：绑定工作区、会话与锚点，签发一次性 permit / 通知已启用的提供者
    → NextStep：事务认领版本（记 owner UUID）/ 凭 permit 读取锚点之前的有限历史
      → Window Host → CLI：凭 permit 一次独立模型生成（SingleAttempt，禁特殊重放）
    ← NextStep：按锚点、版本与 owner 校验并保存同一版本 / 通知状态变化
  ← Renderer：按锚点读取最新版本 / 原生绘制轮尾

打开、切换、重开、回放 → Renderer 按锚点读取 → NextStep 只读数据库
点击刷新 → Host 核验当前锚点 → NextStep 认领新版本 → 同一生成路径
点击建议 → Host 预检锚点和最新版本 → CLI CommandInbox 串行 admission 最终裁决
```

## 锚点与触发

- 持久锚点是 `(workspaceKey, sessionId, productTurnId, assistantMessageId)`。`workspaceKey = workspaceIdentity?.trim() || workspacePath`；`workspacePath` 仍用于文件操作和展示。最终回复 ID 由 CLI 从已完成的助手行解析，不用可见 `rowId`、列表位置、正文哈希或临时投影版本替代。解析必须走 CLI 会话 transcript 的持久消息映射：按持久消息身份取当前分支最新有效回复，不由 Renderer 或宿主用行 `entityId` 相等比较绑定；Renderer 只交出即时行定位（`turnFooterTargetSchema`：`workspacePath`、`workspaceIdentity`、`sessionId`、`rowId`），持久锚点统一由 CLI 的当前分支解析。`entityId` 在投影重建、回放与重挂载间可复用、可重排，相等比较会把建议绑到错误的回复上。
- 自动事件来自 [V4 实时投影提交](../../../apps/zcode-cli/packages/bootstrap/src/zcode-protocol-v4/v4-gateway.ts)中的产品轮从非终态转为 `completedSuccess`，并且存在属于该轮的非空、已持久化最终助手回复。应覆盖队列推进导致的产品轮切分；引导消息不单独切轮。`Stop` Hook、单段文本停止流式输出、会话空闲、缺帧重放、冷恢复和历史窗口加载都不是自动触发信号。
- 中断、失败和纯控制轮不生成。实时成功事实只通知当前已启用且有权处理的提供者，不为关闭、未安装或更新中的插件回补。已存在的合格历史回复在成为最新可操作回复时，可主动点击「生成推荐」，打开时只读取。
- 同一会话重试或编辑后，旧回复退出当前分支，不展示或发送其建议。新生成的最终回复有新锚点，按新回复处理。分叉复制得到的历史不自动生成，也不继承旧会话缓存。
- 已发起的生成不随编辑器卸载取消。如果会话切走、轮次推进或分支变更，迟到结果只能结算原版本，不能换绑或覆盖新回复。读取、刷新和发送独立核验对应锚点和当前动作资格。

## 最小扩展契约

- `conversation.turnFooter`：增加受限的原生插槽。提供者接收可信锚点，实现实时完成通知、`readLatest(anchor)` 和用户触发的 `refresh(anchor, requestId)`，并可发布按锚点的变更通知。读接口无生成副作用，变更通知只使读取失效，不触发刷新。订阅后的初次读取应能拿到当前状态；状态变化与初次读取交错时按持久版本与状态修订号防止旧读覆写新读。
- 独立生成端口：宿主仅接受来自已启用、经授权的轮尾提供者且绑定本地有效回复的请求。读取历史沿用 `sessions.read`；消耗模型额度须单独授予独立档位 `turnFooter.generate`——它是 `EXTENSION_GRANTS` 里与会话档位链、`notifications` 互不覆盖的并列档位，不因持有 `sessions.read` 或 `sessions.write` 而隐含获得——并告知用户该插件可在轮次结束后自动发起额外模型请求。不要把一般会话读取权限视作模型调用权限。
- 一次性事件许可：宿主为每个受理事件（自动 `completed`、手动 `refresh`）签发随命令下发的 `permit`。`turnFooter.history` 与 `turnFooter.generate` 都必须携带 `permit`，且每个 `permit` 恰好可用一次：重放、跨事件复用或第二次到达都被拒绝并计入审计。`permit` 是受理事件与模型调用之间的一次性凭证，防止同一受理事件产生第二次物理请求。
- 宿主兑换生成许可后，CLI 在独立模型执行准入时读取并固定该会话当时已生效的模型（含 provider），沿用自身账号与计量机制。这个时点不是 Renderer 点击或插件认领事务；后续切模型不会影响已准入请求或已有缓存。模型不可用则记录失败，不等待切换，也不回退到别的模型。
- 模型端口只接受有长度、时限和输出预算的文本请求，不运行工具、不进入聊天上下文、不变更会话权限和当前模型。每个已受理版本最多发起一次独立请求，重复提交同一请求标识不重复发送，不用第二次调用修复格式，也不启用会使已发出请求重放的底层重试：重试预算固定为 `ModelRetryBudget.SingleAttempt`（本次请求 `maxAttempts` 收敛为 1），并且必须同时关闭不占该预算的特殊重放路径——鉴权/项目令牌刷新重试（`AccountRequestRetry`）、reasoning 签名拒绝修复重试、off-peak 排队 429 豁免与票据过期重放、请求校验重放（`RequestVerificationRetry`）。这些路径在普通会话请求里合法（`SingleAttempt` 本不限制它们），但轮尾独立生成的物理请求必须至多发出一次。只有确定原调用未发出的校验失败可直接报错；超时或失联且供应商是否接收未知时，记为 `unknown`，等待用户手动刷新。
- 上下文由 NextStep 组织：以原回复为时间上界，取最新用户任务、该轮最终回答及预算内的前序对话，不默认包含附件、完整工具输出、其他会话或之后的消息。持久历史不保存整段用于生成的提示词或模型请求原文。
- 插件输出 `dimension`、`label`、`prompt`，每条具备稳定的组内标识。NextStep 新生成结果为 2–4 条且维度不重复，或明确为空；最多接受 5 条原始候选，逐项校验、去重后按概述 Unicode 码点数稳定排序并保留前 4 条，不增加修复调用。单条、超过 5 条原始候选或非法结构记为失败。通用传输 schema 继续允许 2–5 条，兼容已经保存的版本；Renderer 排序后最多显示 4 条，保留原 ID、版本和正文，不写回 SQLite。宿主仍校验传给 Renderer 的数量、字段类型和长度。只渲染纯文本；插件不能通过结果指定目标会话、工具、权限模式或自动执行动作。

## 插件存储与恢复

唯一权威存储放在 `ctx.extension.dataPath` 的插件私有持久存储，建议 SQLite。每个锚点下按单调 `version` 保留记录；同一条记录只结算自己的状态和结果，不以新的生成覆盖旧记录。记录字段至少包括锚点、版本、`requestId`、认领者 `owner`（每次受理生成时新生成的执行者 UUID，随认领写入并在结算时核验）、触发类型 `auto | manual`、实际模型、状态、时间及结果或非敏感错误码。宿主不另存推荐正文，不在聊天数据库或任务索引中加推荐列。

| 触发或状态 | 规则                                                                                                                                                                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 自动认领   | 事务内检查该锚点没有任何记录，然后写入首版 `generating`。若手动生成先被受理，自动任务也跳过。                                                                                                                                                                               |
| 手动认领   | 使用宿主从本次用户点击分配的 `requestId`。同一 ID 重复到达返回原版本状态；同一锚点有在途版本时，不创建新版本；其余受理后追加下一版 `generating`。                                                                                                                           |
| 提交结果   | 仅匹配锚点、版本和 `owner` 的 `generating` 记录可结算为 `ready`、`empty`、`failed` 或 `unknown`；结算后通知该锚点更新。插件重启换代后新实例的 `owner` 不同：旧 `owner` 的在途记录只能被结算为 `unknown`（重启围栏），新实例不接管、不重发，也不把旧记录改成自己的执行结果。 |
| 读取与恢复 | 读取按 `version` 键定：取版本号最高的记录，不按完成时间排序；变更通知携带 `version` 与状态修订号 `revision`。`ready` 显示建议；`generating` 显示进度；`empty` 显示无建议；`failed` 或 `unknown` 显示当前状态及刷新入口；没有记录时只显示「生成推荐」。                      |

例如 `v1` 成功、`v2` 刷新成功、`v3` 刷新失败：三次记录都保留，重新打开时显示 `v3` 的失败状态，不把 `v2` 当作最新结果。关闭编辑器、切换会话、账户模型切换和插件更新均不新增版本。所有已受理版本首版均保留，不做自动淘汰。没有供应商幂等支持时，进程在请求发出后崩溃意味着结果可能拿不回来；不自动补发是保证不重复调用的代价。

## 交互与提交

- 在最新合格回复的操作栏下增加紧凑单列，最大宽度 28rem，窄窗口自适应。淡色「下一步建议」标题与右侧刷新控件组成固定工具行；2–4 个建议行统一左对齐、可换行。每行根据 `dimension` 的中英文语义映射宿主内置 Lucide 图标，覆盖分析、深化、扩展、写作、修改、验证、实施；未知维度使用探索图标，不增加网络或模型请求。按钮可点击时有 pointer，悬浮改变背景和图标文字，按下轻微反馈，完整提示词沿用 Tooltip，键盘焦点始终可见。
- 初读必须立即显示「正在读取推荐…」和两行轻量占位；最终 `unavailable` 隐藏整个区域。刷新点击后立即显示「正在生成推荐…」，明确区分正在受理的临时动作与插件的持久 `generating`；新版本受理后只显示生成中，不把旧 ready 当作当前版。后台失效重读保留当前布局并显示轻量读取提示。提交等待显示「正在继续对话…」，不冒充生成。错误、空和 unknown 仍各自显示当前事实，读取错误操作只重读。所有等待期间禁用重复动作。
- 进入使用 200ms 的淡入和最多 4px 位移，建议行错峰 30ms；hover/按下约 150ms。只在列表首次显示或版本切换时入场，同版本重读不重复播放。遵循 `prefers-reduced-motion` 关闭位移、错峰和旋转，仍保留文字状态。`aria-busy`、礼貌播报的状态文本和图标按钮可访问名称同时维护。UI 不新增持久缓存或轮询。
- 用户点击建议即请求继续当前会话，按钮的完整提示词可预览。宿主以该控件绑定的锚点及版本核验提交：当前会话、当前分支和最新可操作回复一致，且建议仍来自最新 `ready` 版本。过期就拒绝，不把建议投向新焦点。用户已有未发送草稿不被覆盖或混入这次建议。
- 复用当前会话发送入口和 CLI `CommandInbox`；既有权限、队列、禁止发送条件和 ACK 语义保持不变。单次点击沿用稳定的提交标识（`submit` 请求的 `commandId`）；等待受理期间防重复提交。锚点、分支与最新 `ready` 版本的最终 stale 核验在 CLI `CommandInbox` 的串行 admission 内完成：per-session admission gate 持有期间按 `admissionSeq` 顺序判定，竞态提交最多一次 `accepted`，其余返回 `stale` 或 `blocked`；宿主与 Renderer 的锚点核验只是前置过滤，不作为最终裁决。选择建议本身不授予插件 `sessions.write`，不绕过之后的工具确认。生成完成不会自动提交。
- Desktop continuous 不因该能力改变对话投影或已接纳队列；手机 replayable 不注册轮尾提供者、不读取插件缓存、不把历史回放解释成新生成事件。后续做远控支持须另定目标 Host 的读取和恢复协议，不在首版开口。

## 验收场景

| ID     | 场景                                                                                                            | 必须观察到                                                                                                                                                 |
| ------ | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NST-01 | 一轮有多个模型片段、工具调用或队列切分                                                                          | 每个符合条件的成功产品轮只触发一次；流式中、引导续跑、失败和中断不触发。                                                                                   |
| NST-02 | 成功后重复送达完成通知，切到另一会话再切回，关闭重开编辑器，重启应用后打开                                      | 建议与版本一致，NextStep 模型请求计数仍为 1；重放和重挂载只读。                                                                                            |
| NST-03 | 安装后打开既有旧会话                                                                                            | 最新合格回复有「生成推荐」，打开次数不影响调用数，点一次才从 0 变为 1；更早回复不补生成。                                                                  |
| NST-04 | 连续点击刷新、重复投递同一点击，再做一次独立刷新                                                                | 在途时只有一个被接受；重复 `requestId` 不增加调用数；同一 `permit` 二次调用 `turnFooter.generate` 被拒；一次新刷新追加一版并保留旧版，恢复后显示最新记录。 |
| NST-05 | 生成期间切走；模拟模型超时、非法输出、鉴权失效、签名拒绝、off-peak 排队等特殊重放类失败与宿主中断；插件重启换代 | 结果只归原锚点，物理模型请求恰一次、不自动重发，失败或未知可恢复回显；旧 `owner` 在途记录结算为 `unknown`，新实例不接管；手动刷新能开启下一版。            |
| NST-06 | 重试、编辑或分叉后返回；让旧结果迟到并尝试点旧建议                                                              | 新回复和不同会话不复用旧记录；历史复制不发起生成，旧按钮不可提交。                                                                                         |
| NST-07 | 点击最新建议，另有未发送草稿；验证常规权限流程                                                                  | 最多提交一次，发送到按钮绑定的会话，草稿不被覆盖，Agent 工具仍按当前权限执行。                                                                             |
| NST-08 | 切换有效模型后查看旧推荐并手动刷新                                                                              | 查看不调用模型；刷新使用新模型并按该模型记录用量，原版仍可由存储核对。                                                                                     |
| NST-09 | 打开远程工作区或通过手机远控回放同一会话                                                                        | 不渲染本地扩展轮尾、不重复生成，对话与发送路径照常可用。                                                                                                   |

使用可计数的模型 fixture 同时断言调用次数、插件持久版本和桌面轮尾回显。协议检查覆盖实时终态与冷恢复区分，插件检查覆盖原子认领、`permit` 一次性核销、`owner` 围栏与故障结算，桌面验收覆盖关闭、切换、重开、手动刷新及点击提交。以上为待实现、待执行的验收合同；官方候选入口为 `packages/desktop/test/e2e/plugins/extensions/manual-review/pending/plugin-management-nextstep-turn-footer.test.ts`，逐条登记见 [插件生命周期用例目录](../../plugin-management-lifecycle-case-catalog.md) 的 PLM-EXT-NST，登记时即 not run、not promoted。
