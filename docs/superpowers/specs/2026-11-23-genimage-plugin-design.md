# GenImage：ZCode 生图画布插件初步设计

- **状态：**按用户补充修订为无限画布与成图派生方案。本轮只搭无计费开发底座，不代表真实生成、持久化或 Desktop 联调完成。
- **宿主基线：**`develop @ 1a17f228`；设计分支 `feature/genimage-plugin`。
- **核心决定：**GenImage 是独立生图工作台。模型、参数、生成任务、历史和产物归插件；ZCode 会话只负责**拉起、引用、交接**。切换会话聊天模型不改变任何 GenImage 设置。

## 1. 用户目标与首版范围

典型旅程：在桌面本地会话打开 GenImage → 在无限画布浮窗里配置本次生成 → 生成原图节点 → 选中原图并点「基于此图修改」 → 写修改要求并确认发送该原图和提示词 → 新图作为子节点出现，可从原图或任意结果继续分支 → 导出或引用选中的结果。源图不被修改或覆盖。

| 首版承诺                                                                                 | 后续，不作为本次验收条件                                          |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Desktop 本地会话；会话侧栏内的市场详情页和对话工具卡片两条入口                           | Web、手机远控、桌面远程工作区、全局常驻画布、主动加入宿主推荐列表 |
| 无限画布铺满工作台：平移、缩放、节点选中与拖动、聚焦谱系；功能以浮窗展示                 | 多画布、多人协作、跨设备同步、任意形状或图层编辑                  |
| 一家真生图服务商、单张文生图及以一张已有成图作输入的指令式改图；子图保留来源并可继续派生 | 多源合成、外部参考图导入、蒙版、笔刷、批量、多服务商、自动重试    |
| 原图显式导出到当前工作区，将已导出的所选产物路径加入当前会话草稿                         | 自动提交聊天、跨会话投递、大图内联以及未经验证的附件承诺          |

**三类方案取舍：**① 推荐独立 MCP Apps 插件，最大化复用现有插件边界；② 内置插件虽可一起分发，但会耦合宿主发布，尚无需要；③ MCP + 外部网页可做独立工具，却不满足会话侧栏画布要求。首版不改宿主；如果必要能力未通过验证，回用户评审，不默默改成内置或绕开权限。

## 2. UI/UX：无限画布

### 2.1 全视口画布 + 页内浮窗

```text
┌─────────────────────── 画布视口 ───────────────────────┐
│ [GenImage · + 新生成]                        [历史][设置] │
│                                                         │
│   ┌ 原图 A ─────┐        ┌ 改图 B ─────┐                 │
│   │   缩略图    │ ─────→ │   缩略图    │ [基于此图修改]  │
│   └────────────┘   └──→ └────────────┘                 │
│                    ┌ 改图 C ───┐                        │
│                    └──────────┘       ┌ 生成／修改浮窗 ┐ │
│ [缩小][100%][放大][聚焦全部]          │ 来源 · 要求   │ │
│                                       └───────────────┘ │
└─────────────────────────────────────────────────────────┘
```

- 画布占满视口。新生成/改图、历史、设置、任务状态、选中详情、导出/引用以及缩放控制均放在浮动工具条、节点菜单、浮窗或确认层，不永久划出固定侧栏或把画布替换为表单。浮窗相对视口锚定，节点与连线才随画布变换。窄窗口只打开一个主浮窗，可用底部浮层且限制高度；不影响缩放和关闭，内部自己滚动。
- 空白拖拽平移、滚轮按指针缩放、节点拖拽改变布局不改变关系；键盘可选中节点、缩放、聚焦全部和跳转到原图/子图。点击空白清除选中时不丢已填表单；Esc 关闭最上层浮窗，恢复触发点焦点。可见区域渲染有界缩略图，连线从边数据实时派生，不把视觉布局当成业务事实。
- 选中节点时凸显其上游与直接子节点，点击父图或子图可以定位；历史点选结果也聚焦对应节点。成功结果落在源图旁的空位，不抢走用户正在查看的其他节点；失败只更新任务浮窗，不创建伪结果。默认主题与语言遵循宿主，明暗与简中/英文、对比度、可见焦点、屏幕阅读器关系文本与减少动效须验收。
- 只声明 MCP Apps 的 `fullscreen`（宿主侧栏），浮窗都在同一沙箱页面，不另开系统窗口，也不用 `pip`。实际依照 [插件展示模式](../../../docs/plugin-ui-display-modes-spec.md)。先测 360 / 600 / 900 CSS px，没有页面横向溢出。

### 2.2 设置与交互状态

```text
设置                        历史
生图服务：OpenAI · 云端       [生成中] 模型 · 比例 · 时间
凭据：已配置／尚未配置        [缩略图] 已完成 · 尺寸 · 时间
  [管理 GenImage 密钥]       [!] 结果或计费未确认 · 查看详情
默认模型：[可用模型 ▾]       选择一张成图 → 回到画布
默认比例：[比例 ▾]           删除记录 → 确认（导出文件保留）
工作区存储：数量 / 已用容量
[返回画布]
```

「管理 GenImage 密钥」使用目标版本已验证的插件配置入口；若没有公开的直达 API，则显示返回插件管理的明确步骤，不伪造站内跳转。首版不展示种子、外部参考图上传或自动重试等不支持的控件；设置页不提供会实际出图的「测试连接」。

**无密钥先打开画布（S0 候选）**：在敏感字段保留 `sensitive: true` 的同时，用空字符串作为未配置的默认值。当前[变量展开实现](../../../apps/zcode-cli/packages/adapters/src/plugins/mcp.ts#L431)只拒绝 `undefined`，因此有望在未填密钥时注册同一个 MCP 服务。服务端须将空值当作未配置，禁止任何生图请求；首屏应能显示配置引导，不依赖会触发审批的读取工具。用无费用桌面测试验证全新安装、清除密钥后重载、无密钥时零供应商连接；未通过就保留先配置再打开的流程。

| 场景               | 处理与建议文案                                                                                                                                                                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 首次打开／未配置   | 默认先走市场详情页的 GenImage 专属配置，填入密钥后再打开画布。当前清单引用缺值可能阻止整个 MCP 服务注册，不能依赖画布内空态完成首次设置。若目标版本实测有安全的缺值启动方案，再启用画布内「配置生图服务」空态。已打开时设置展示连接状态、模型、默认比例和凭据管理位置，不读出密钥。                       |
| 从会话拉起         | 带入一条待编辑需求；有未保存草稿时显示「使用会话需求替换当前草稿？」或保留当前草稿。打开不生成，不自动读取聊天记录、附件或其他会话。工具未就绪时，随插件提供的使用说明或 skill 指向 GenImage 专属配置和重开会话，不让会话自行改用 Bash 或别的付费接口。                                                   |
| 准备生成           | 在按钮旁标明实际接收方，例如「提示词将发送给 OpenAI，可能产生服务商费用」。首次认同另行记录；点击「生成一张」才请求执行，无自动提交、空白提示词禁用；校验错误在对应字段展示。                                                                                                                             |
| 待受理／执行       | 「提交中，可能需要在 ZCode 中确认」→ 插件受理后「生成中」。重复点击不可创建新任务；保留当前图片。只有服务商能提供确定进度时才显示百分比；首版用非定量状态。                                                                                                                                               |
| 停止等待／取消     | 若确认尚未发出，显示「已取消，未发出请求」。已发送时使用「停止等待」，提示「服务商可能仍在生成或计费」；仅在服务商明确确认时显示已取消。关闭画布不是取消按钮。                                                                                                                                            |
| 失败与超时         | 分开显示未配置、权限拒绝、密钥无效、账户额度/付款、模型不可用、限流、内容拒绝、下载/落盘失败和任务结果未知。账户额度/付款提示去服务商检查账单，模型不可用提示换模型，均不把「重试」作为主按钮。未知条目提示「结果或计费未确认」，优先查状态（服务商支持时）；若要再次提交，明确可能产生新费用并二次确认。 |
| 生成成功／产物缺失 | 展示图片、模型、尺寸和时间。找不到图片时提示「原图已不可用」，禁用导出/图像引用，不把缓存缩略图当作原图。                                                                                                                                                                                                 |
| 产物动作           | **导出 PNG** 写出最终文件，不提交聊天；**引用到会话** 将已导出文件的相对路径和必要摘要放入当前输入框，不点发送。首次引用尚未导出的图时提示先导出，不静默写文件。引用成功提示「已添加到会话输入框，可在发送前移除」。                                                                                      |

「引用到会话」默认只包含已验证存在的工作区相对路径与必要的格式、尺寸，不默认包含原始提示词、完整配置、秘密或服务商原始响应。同一面板后一次引用替换前一次，首版不累积多张。预览图引用仅在 S0 验证目标版本的 composer 和目标视觉模型后另行启用；不能把路径说成附件。导出不等于发表，用户自行按发送才提交聊天。没有活跃可编辑输入框、会话已切换或导出文件已移动时停止并提示，不偷偷投递。

## 3. 插件形态与各层责任

| 组件                            | 持有与执行                                                                                                                 | 明确不做                                                                              |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| ZCode UI Plugin / MCP Apps 宿主 | 创建会话级沙箱面板、传主题语言、连接插件工具与资源、按已有机制审批、在当前会话输入框接收上下文；插件配置层保存与注入敏感值 | 不存画布业务数据、不调用生图 API，宿主页面及聊天不读取密钥，不自动发送                |
| GenImage 画布页（打包 HTML/JS） | 维护焦点/缩放等视图态、显示服务端状态、转发明确的用户操作；使用官方 MCP Apps `App`                                         | 不从页面 `fetch` 生图服务，不接触凭据，不直接操作文件系统；`widgetState` 不当业务存储 |
| GenImage 本地 stdio MCP 服务    | 持有任务、配置、项目历史和产物；校验入参、用户许可与持久状态；提供只读资源和显式导出                                       | 不从任意会话导入聊天历史；不开放可触发付费的模型工具；不注册后台 Hook                 |
| 生图适配器（同一插件代码）      | 以统一接口调用所选供应商；规范化尺寸、错误、结果与远端状态，实施网络边界                                                   | 不单独部署；不自动切换到其他服务商、宿主聊天模型或静默重试                            |

安装包建议含 `.zcode-plugin/plugin.json`、可执行的 `dist/server.mjs`、打包的 `dist/canvas.html` 和必要的离线资源。`mcpServers` 注册 stdio 服务；`ui.surfaces` 注册 `availability: "session"` 的 `canvas` 面板；服务返回 `ui://genimage/canvas.html`。页面通过 MCP 与本机服务通信，本机服务才访问云端。仓库内新工程和个人市场产物遵循[插件工程化规格](./2026-11-23-plugin-workspace-design.md)，本地市场保留 `genimage@genimage-local`，不承诺跨市场身份自动迁移。用户只安装一个插件，运行时不跑 npm/npx 或编译器；宿主 Node 机制可能优先用用户 PATH、再走满足条件的桌面回退。**无全局 Node 的干净环境是发布门槛，不承诺已支持**。

### 3.1 会话及工具契约（提案）

| 接口                                                                                                                              | 可见性 / 作用                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open_canvas({ brief? })`                                                                                                         | `model, app`；首版 `brief` 为纯文本，上限 2,000 个 Unicode 码点，超限不截断覆盖草稿；返回待编辑文本；工具定义的 `_meta.ui.resourceUri` / `_meta.ui.surface` 负责路由，不创建付费任务、不接受权威会话 ID。对话工具结果提供打开入口，不依赖自动跳转一定成功。                              |
| `read_canvas()` / `list_history({ cursor? })`                                                                                     | `app`；有界分页读取当前工作区选图、任务及非敏感配置摘要。                                                                                                                                                                                                                                |
| `save_settings({ modelId, aspectRatio, revision })` / `record_consent({ policyVersion, providerId })`                             | `app`；更新插件非秘密配置并防并发覆盖；不包含 API 密钥、不发起生成。                                                                                                                                                                                                                     |
| `start_generation({ requestId, prompt, modelId, aspectRatio, sourceAssetId?, consentVersion })`                                   | `app`；校验后原子受理，返回 `jobId`、状态、单调修订号；同 ID 同参数返回原任务，异参数冲突。权限拒绝应在插件受理前生效。                                                                                                                                                                  |
| `get_job({ jobId })` / `stop_job({ jobId })` / `select_image({ assetId, revision })` / `delete_history_item({ jobId, revision })` | `app`；查询、显式停止、选图和删除终态记录均不发起新的生图请求。删除前页面明确确认，服务拒绝删除活动任务，保留独立幂等记录和已导出文件。                                                                                                                                                  |
| `resources/read`（预览）/ `export_image({ assetId, fileName, operationId })`                                                      | 从服务端读取有界缩略图；导出工具仅 `app` 可见、读取指定 ID 的原图，写到工作区约定目录 `genimage/`，初版不覆盖。保存成功才登记相对路径供后续引用；重试复用 `operationId`，不得重复写或覆盖。原文件有变动或同名冲突时提示选择新文件名；不擅改 `.gitignore`，并提示导出文件可进入版本管理。 |

模型工具的唯一设计用途是打开画布。`visibility: ["app"]` 只确认不会向模型广告该工具，**不是**免审批，也不能单独当作付费操作的授权边界。S0 必须通过无费用 fixture 验证模型路径不能执行生成、修改设置或导出，包括工具未列出时的精确名称请求；若现有宿主无法提供可信来源校验，真生图不得上线，需回评审决定可验证的隔离方案或最小宿主修补。页面只在点击「生成一张」后调用受理；服务端独立校验配置、同意记录、限流和单请求幂等。`sendMessage` 的用户手势能力不能移作生成手势证明。

### 3.2 固定接入首个服务商

建议首版选 **OpenAI Images API** 作真服务商验证对象：使用固定 HTTPS 目的地及已实测可用的单图模型清单，模型 ID、比例/实际尺寸映射、PNG 输出格式、错误和供应商幂等/状态能力在验证阶段冻结。通用接口仅包括读取能力快照、提交一次、规范化响应；必须验证能以单图真实修改，在不支持修改的模型上不得伪装成普通文生图；查询/取消是可选能力，不为不存在的能力显示入口。不加可输入 Base URL、任意模型 ID 或自动回退。发布前核对适用地区、账户资格、条款和费用；没有可用凭据时只运行本地 fixture，不把模拟当成真实接通。

## 4. 产物谱系、生成时序与恢复

- **节点和边：**同一工作区画布中的原图是根；每张子图有一个不可变的 `sourceAssetId`（边方向为源图 → 子图），同一源图可以有多个子节点，子图可继续作为源图。派生关系来自显式选择的实际输入，不从相似提示词、创建时间、节点位置或手画线推断。图片文件、生成参数及来源不可被改图覆盖。
- **事务与恢复：**后端在受理时验证源图存在、属于该画布且可用，把其 ID 与内容校验摘要写入任务快照，发出前复验；结果文件落盘后，在同一 SQLite 事务发布资产、布局节点和有向边。只允许已存在源图指向新资产，新资产通过 `sourceAssetId` 记录来源，首版没有手工重连、跨画布关系或环。失败/结果未知时没有成图或边；晚到结果仍按任务围栏结算，不抢占新任务。
- **布局与删除：**`board/layout` 以单一修订号保存节点坐标；拖拽仅在结束时提交，版本冲突重读并提示。相机/缩放属于当前面板视图，不覆盖其他窗口的业务布局。活动任务引用的源图或已有子节点的源图禁止删除；可删除已无后代的结果并保留独立幂等记录与已导出文件。不静默级联删除。
- **本轮开发骨架：**现有无计费骨架是新应用的行为参考，归档目标为 `plugins/legacy/genimage-dev/`；新工程目标为 `plugins/apps/genimage/`，由[插件工程化规格](./2026-11-23-plugin-workspace-design.md)规定 React、宿主主题和 `dist/market/` 安装产物。旧骨架的安装入口用真实 MCP Apps stdio，开发预览用只绑定回环地址的静态 HTTP；二者读取同一个自包含 HTML，内置标明为模拟数据的谱系。开发预览、市场安装与 Desktop 真实接线分别验证。本轮工程化仍不开放真实付费工具、不写用户图库、不调用模型、不自动安装市场。

```text
会话 open_canvas（仅 brief）→ MCP Apps 画布 ← 市场详情页直接打开
    用户生成 → 宿主权限 → GenImage 持久受理（幂等 + 并发约束）
                                ↓ 单次提交、固定本次模型和参数
                            生图 Provider
                                ↓ 校验、落盘、持久结算
    画布按 jobId 读取修订号 ← 本地 MCP ↔ SQLite / 插件图片目录
    用户导出 → 工作区文件；用户引用 → 当前 composer → 用户决定是否发送
```

- **所有者：**MCP 服务是唯一业务入口，SQLite 是任务与索引权威；允许同工作区多会话/窗口各有服务进程，不能用各进程内存变量充当全局锁。事务保证同一作用域最多一个活动任务；第二条新任务返回忙，首版不排队。读取、刷新、重开面板不产生写入、补发或供应商请求。
- **状态：**`accepted → dispatching → running → succeeded | failed | outcome_unknown`。只在可信地确认未发出或供应商确认已取消时结算 `cancelled`；已发出不能确定时用 `outcome_unknown`，不能称「未扣费」。发送前持久写入提交围栏；记录仍在该围栏前且旧执行者失效，则结算为未发出，不自动调度。网络断开/超时/进程崩溃，只要可能已发出则进入 `outcome_unknown`，没有供应商可查询的 ID 时不补偿重发。记录区分「上游已成功但图未存」和「上游结果未知」。
- **执行围栏：**每个执行者都有 owner 和租约/代次；写结果以任务 ID、状态和 owner/代次校验，旧进程失去所有权后不能提交，不把任务转交新进程重发。恢复只处理失效 owner，不能仅因为新 stdio 进程启动就标记其他进程任务未知。租约只判定是否能继续写状态，不能用超时推断不计费。
- **页面生命周期：**受理并持久提交后短调用返回；页关闭或切标签只停止本页查状态，不自动取消已受理任务。仅在 MCP 进程仍存活时承诺继续处理；会话重载、禁用或应用退出可终止子进程，重开按上面规则恢复，不承诺退到系统后台仍会完成。页面可见时有界查询，失活时停查；没有通用双向进度，不依赖它。
- **受理与恢复：**页面每次明确点击只分配一个 `requestId`，持久化唯一键为 `(workspaceKey, requestId)`，同时记录参数摘要。响应丢失或页面重建时先查询活动与最近任务；不创建新 ID、不自动重提。重复调用只能复用原 ID，参数不同直接冲突。另一窗口点生成时若已有活动任务，返回其 ID 和「另一处正在生成」状态。删除历史或图片不能删除幂等保障：短期保留不含原文的幂等记录，超出公开受理期的旧 ID 由服务拒绝，期限与 ID 校验规则在 S1 冻结并测试。
- **显式重试：**已生成、已失败或结果未知的任务保留原记录；用户选择新尝试才分配新 ID。禁止 SDK、HTTP 自动重放，包括“便捷”重试、重定向重发和未提供承诺的上游幂等假设。

## 5. 数据、权限与成本边界

| 数据               | 所在地与规则                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 插件设置／凭据     | 非敏感设置及同意版本由插件管理；密钥通过清单 `userConfig.sensitive` 注入 stdio 环境，不进页面、普通配置 JSON、工具输入/结果、命令参数、日志或 SQLite。宿主用独立的私有明文 JSON 保存该值，依赖用户文件权限；**不是**系统密钥链或加密存储。按用户和插件安装管理凭据，不以工作区设置为账户隔离手段；修改后先要求开启新会话或显式重建，旧进程的环境变量不会被同步改写，须在目标桌面验证生效范围。 |
| 工作区身份         | 以插件进程启动时的可信 `${ZCODE_PROJECT_DIR}` 绑定并规范化本地工作区，不接受页面传入路径作为身份，插件按安装身份和工作区分区。现有 stdio 接线未证明能读取可信 `workspaceIdentity`：首版只承诺可独立规范化的本地物理目录；共享同一目录但要求身份隔离的虚拟项目不在首版。若宿主无法识别并阻断该场景，须在 S0 缩减实际支持范围或回评审。                                                          |
| 私有资源授权       | 个人来源的常规 MCP 进程按会话隔离，插件数据目录仍跨进程共享；`resources/read` 只传 URI，不能依赖它携带可信会话元数据。每次读取用**启动时绑定的工作区键 + 不透明 asset ID**查询，工作区未可信绑定时只可读静态页面，不能以可猜 ID 或 URI 当作授权。需要验证跨工作区工具和资源访问均被拒绝。                                                                                                      |
| `settings / board` | 保存有效模型 ID、比例、同意版本、节点坐标与布局修订号；首版每工作区一个画布。提示词草稿默认保留在当前页面，关闭后不承诺恢复；只有已受理任务的提示词进入本地历史。                                                                                                                                                                                                                              |
| `job / asset`      | 保存任务 ID、幂等键/参数快照、阶段和终态修订、真实上游 ID（若有）、分类错误、时间；保存图片 ID、工作区、文件名、MIME、尺寸、字节数、内容校验。原图与缩略图写插件数据目录，用独占临时文件、原子落盘和事务发布索引，处理落盘先于事务完成的孤儿。                                                                                                                                                 |
| 保存期限与清理     | 评审建议每工作区先按 **100 张或 512 MiB** 上限验收，两者先到为准；达到上限就在发出新请求前提示处理，不静默删旧图。用户可明确删除已结束的记录，已导出的文件不受影响；幂等记录和诊断须有界且独立保留。禁用、换凭据和同身份更新不自动清数据。当前卸载实现可能删除插件数据；使用或卸载前提示先导出，只有目标入口实测保留才承诺卸载后能恢复。                                                       |

- **目录连续性：**用操作系统规范绝对路径与 `realpath` 作为 S0 候选，依平台实测大小写、短路径、符号链接/junction 与挂载别名；不要跨平台盲目折叠大小写。不接受难以确认是同一受支持本地目录的别名。目录迁移或重命名首版不自动迁移历史，旧数据不会被新目录自动读取或删除。正式发布后保持插件 ID 和来源不变；变更视为单独的数据迁移项目。
- **大图：**工具结果只带 ID、状态和元数据，不承载原图 base64。页面按需读取缩略图（设计目标 PNG/JPEG/WebP ≤ 1 MiB），当前宿主 `resources/read` 上限 8 MiB；引用图片仅支持 PNG/JPEG/WebP 且单张解码后上限 4 MiB；原图基准上限建议 32 MiB，由服务读取与导出，不经页面桥传递。做签名/尺寸/解码像素与字节上限检查；文件已满/失效时不将任务误标成功。
- **路径：**工具只接受安全文件名和自己存档的 asset ID；工作区路径实时校验，拒绝路径穿越、绝对路径、Windows 设备名与符号链接/junction 逃逸，用独占创建及可信目录边界防覆盖和竞争；具体文件发布原语需跨平台验证。回交文案只暴露工作区相对路径，不暴露插件缓存或绝对路径。
- **网络与隐私：**只有明确同意后，发送当前提示词与必要生成参数给指定供应商；基于成图修改时另外明确展示将发送的那张源图，仅在确认后传输；不开启默认遥测、不复制会话正文。凭据只用于供应商授权路由；如供应商返回图片 URL，下载限定 HTTPS、允许域、受控跳转与大小，不能向下载域转发密钥；无可信 URL 合同的适配器只收内联图像数据。脱敏错误不输出上游原始响应。软件不能判定外部费用或合规保留期，界面不声称「未计费」「仅本地」等未经证实的状态。

另有两项首版阻断验收：

- **A9 无限画布：**宽窄视口平移缩放、拖动和聚焦后连线仍锚定正确；设置、历史、生成和所有工具不挤占画布；支持键盘；重开恢复节点坐标，不重发任务。
- **A10 产物谱系：**A → B、A → C、B → D 重开后完整；用 B 修改时请求只使用 B 的原图，A/B 不变。跨工作区源图被拒、失败不造边、删除规则不破坏谱系；模拟改图与真实模型验证分别取证。

## 7. 项目组建议与用户评审项

**来自团队的取舍：**产品范围按用户补充增加从成图继续改图；架构建议只有 `open_canvas` 对模型暴露；UI/UX 将生成、导出、引用区分为独立动作；测试将不重复付费、未知状态和不误投设为发布阻断。技术负责人建议先在独立插件源码中交付，不把插件或供应商集成塞进 ZCode 主仓库；本分支承载修订规格与无计费开发底座。

**评审结论：有条件进入用户评审，不是实施或发布放行。** 技术负责人和独立评审员提出的缺密钥启动、跨工作区资源授权、只向页面开放付费工具、幂等键与恢复、错误分类及网络验收，已并入上文。S0 需给出实测证据或回评审的明确决定；尤其是在仅从模型工具清单隐藏的情况下，不能把「模型不能触发付费」当成现成能力。真实供应商接通、持久化实现和桌面联调不在本轮骨架交付中。

**请用户优先评审：**① 首个云端服务商（建议验证 OpenAI）及内置成图派生是否覆盖用例，外部参考图和蒙版是否前移；② 是否接受用 GenImage 专属插件配置写密钥、在画布内选择模型和默认参数；③ 原图导出后把路径加入当前会话草稿是否够用，还是首版必须直接带可见图片。模型 ID、发布版本和平台覆盖属于验证结果，不作为已承诺事实。
