## Context

以本轮确认的设计为准，替换此前被否决的 `apps/plugins/` 迁移方案。**仓库根下的 `plugins/` 是独立 pnpm workspace；`plugins/apps/` 存放全新工程，现有源码只作参考。** 先修订并归档规格，再推进工程搭建；不升级 ZCode 主应用技术栈，不把本轮工程化当成新增 GenImage 付费生图或改造 NextStep 产品行为。

## 1. 设计落档与目录

- 在 `docs/superpowers/specs/2026-11-23-plugin-workspace-design.md` 记录工作区布局、公共包接口、宿主主题流、构建契约、旧实现退役条件和验收。更新现有 GenImage 设计文档和 NextStep `SPEC.md` 的当前工程路径及阶段说明，保留原有产品和运行时契约；明确区分新工程目标与已交付状态。文档落档在源码变更之前，不提交或推送 Git。
- `plugins/` 内建立 `pnpm-workspace.yaml`、`package.json`、独立锁文件与共用工程配置。成员仅匹配 `apps/*`、`packages/*`；不改主仓库 workspace 成员。新工程路径为 `plugins/apps/genimage/`、`plugins/apps/nextstep/`，不把旧源码目录搬过去后原地重构。
- 将现有 `genimage-dev/`、`nextstep/`、`marketplace.json` 原样放入 `plugins/legacy/`，维持相互间相对路径；`legacy/` 不参加安装、构建和发布。整理归档时同步更新仍依赖旧目录的测试和文档，不允许旧测试因搬目录而静默失效。已经在 ZCode 登记的旧市场不会自动换址，不自动操作用户配置。对应新 app 承接并通过验收之后才考虑移除旧实现；不把本轮开工授权当作删除授权。

## 2. 公共包和依赖门禁

- `plugins/packages/ui/`：专放由固定版本 shadcn CLI 拉取的元组件和生成所需内部工具。提交 CLI 配置、组件清单和产物；需要调整时走 CLI 更新或 `uis` 包装，不手改生成组件。唯一允许声明依赖和导入 `ui` 的消费者是 `uis`。
- `plugins/packages/theme/`：对接公开的宿主上下文，集中处理首帧提示、初始化、部分更新、语义令牌转换和受控回退；不依赖 React 组件，不回写宿主，不保存独立主题偏好。验证颜色、字体、圆角等实际可用值，忽略未知字段及不受支持的样式，不导入宿主私有实现。
- `plugins/packages/uis/`：唯一公共组件入口，直接再导出无需适配的元组件，包装有统一样式、宿主参数或交互约束的组件。由 `uis` 的 Provider 及公共样式把 `theme` 的输出应用到插件根节点，再用 Tailwind v4 的语义变量影响 shadcn 与业务组件；不修改生成文件。应用只接入 `uis` 公开接口，不直接导入元组件或自行复制主题桥接。
- 依赖方向为 `apps/业务 → uis → ui、theme`。门禁同时验证包清单与源码导入，拒绝 `ui` 的直接依赖、深层导入、相对路径及别名绕过。其余共享能力待出现实际复用需求再抽取，不预置空包。NextStep 无独立 UI，不引入这三层 UI 依赖。
- 精确版本统一写在工作区 pnpm `catalog`，所有第三方直接依赖以 `catalog:` 引用，内部公共包用 `workspace:`。启用严格目录模式并阻止显式版本绕过，要求冻结锁文件安装。以实施时核验的最近兼容稳定版为准：React、Vite、Tailwind CSS v4、shadcn CLI、TypeScript、类型感知 Oxlint；开发 Node/pnpm 遵循根 `mise.toml`。浏览器、Node 类型配置分离，启用严格 TS、未检查索引和精确可选属性，lint 拒绝不安全类型、未处理 Promise 和 Hooks 规则违规；生成源码不靠手改来通过 lint。

## 3. 新 app 与安装产物

- GenImage 新建 React + TypeScript 应用与 Node stdio 服务，参考旧版保留 `open_canvas`、`brief` 回填、资源 URI、展示模式与画布核心交互，不接真实计费服务。开发预览可热更新和模拟宿主；安装后的页面使用真实 MCP Apps 上下文。宿主 `data-theme` 控制首帧，握手后的主题、样式令牌及已支持的上下文字段单向更新，经 `theme → uis` 生效，不重建画布、不丢草稿；没有第二个生产主题来源。避免放宽 CSP。参考 `buildPluginUiHostContext.ts`、`pluginUiStyleVariables.ts` 和现有站点插件 MCP App 接入。
- NextStep 新建严格 TypeScript 的无 UI 工程，以旧 `SPEC.md` 和回归用例为准承接扩展入口、命令、SQLite schema、worker 和执行代际机制，不改变宿主轮尾渲染。优先以旧版测试验证新产物，而不是重写断言来适配新行为。
- 每个 app 的构建生成自身目录内的 `dist/market/marketplace.json` 和 `dist/market/<plugin>/.zcode-plugin/plugin.json`、运行时入口及资源。GenImage 页面产物是 stdio 服务可返回的自包含 HTML，NextStep 产物含可加载 ESM 与 SQLite worker。工作区共享包随产物打包；最终目录不含开发源码、`node_modules`、链接或 checkout 依赖。临时目录构建、校验后发布，不提交产物。
- 保留既有市场名称和插件 ID：`genimage@genimage-local`、`nextstep@dev-zcode-1b53af4a`；manifest 与 listing 同步升版。分别交付干净的 `dist/market` 路径，避免 ZCode 复制整个开发树。用隔离环境验证同 ID 换址与升级后再提供手动迁移说明；刷新不会自动发现新路径，不要求用户卸载插件，不直接编辑用户市场记录或缓存。

## 4. 分阶段推进与验收

1. **规格落档 → 公共底座。** 检查基线，先写规格和分阶段实施清单；归档旧实现并建立 workspace、catalog、严格 TS/lint 与依赖门禁。先覆盖归档、目录依赖和越界导入的工程回归。实现并验证 `ui → uis` 的单一入口与 `theme → uis` 的主题消费；不用旧项目填充新 app 目录。
2. **GenImage 新 app。** 从干净产物走 stdio 启动、工具 schema、`brief`、HTML 资源与错误处理。覆盖 Desktop 初始明暗和实时主题、令牌缺项/非法值、草稿和焦点持续、键盘及窄窗口；用现有 MCP Apps 设施和可重复浏览器验收，普通浏览器预览不替代 Desktop。无全局 Node 的打包 Desktop 启动单独验证并据实报告。
3. **NextStep 新 app。** 从构建后的入口跑现有 SQLite、并发、旧数据、崩溃/热重载回归。更新 `plugin-management-nextstep-turn-footer` 的 E2E 及 file fixture，使其验证新产物；inline E2E 不替代真实市场安装。
4. **交付。** 验证工作区冻结安装、catalog/边界检查、typecheck、lint、build 及两个干净市场产物的独立安装与更新；执行仓库 `pnpm typecheck`、`pnpm lint`、架构检查，检查 Hooks 实际诊断。记录真实结果和环境未覆盖项，给出开发和手动安装指引。旧实现仍保留至对应新 app 验收完成并确认退役范围。
