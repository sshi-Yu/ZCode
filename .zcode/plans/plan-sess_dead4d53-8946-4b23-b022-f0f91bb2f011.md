## 背景

桌面已经有「生图」入口和本机 Host 生图服务，页面仍依赖 GenImage 插件，模型设置目前只有单独的 API Key 卡片。按复审稿实施原生工作台、双栏模型配置与工具模型绑定。首批采用 OpenAI Images 兼容协议，工具依次接入 Git 提交说明、自动标题。FrostFox 在迁移与本地验收完成后联调。

## 实施顺序

1. **确定契约与验收。** 运行 `node scripts/check-workspace-freshness.mjs`、`pnpm architecture:check --changed`，读取 `image-generation` 与实际受影响模块的架构上下文。先更新生图服务 `CONTRACT.md`、双栏设置规格、插件兼容说明和相关用例目录／覆盖矩阵，再维护桌面 E2E 与 CLI 回归。功能图谱从现有 `surface.provider-settings` 关联生图设置、原生工作台及工具模型消费者，记录实际提交链路。保留现有本地草稿与原型文件。
2. **原生工作台与兼容。** 在 `WorkspaceShellLayout.tsx` 保留 `genimage` 导航，移除原生入口对 `ExtensionViewPane`、`ExtensionAppViewBridge` 及插件状态的依赖。从 `useBaseWorkspaceServices()` 取得 Host 服务，将 `remoteServiceAccess.ts` 的生图代理从扩展开关拆出，沿用 `windowHostAttachmentRpcPolicy.ts` 的本机桌面发布边界。复用现有宿主页头、窗口控件、弹窗和 `IPlatformService.saveFile`。宽区提供画布与浮层，窄区提供结果列表与底部生成面板。先以现有固定模型契约验证无插件打开、切项目、原图导出和重启。通用扩展与历史会话工具卡走各自兼容路径。通用凭据 RPC 在共享注册处统一拒绝访问生图私有命名域。
3. **生图连接、模型设置与存储升级。** 在 `SettingsPage.tsx`、`ModelProviderSection.tsx` 与 `settingsNavigation.ts` 复用双栏布局、选中状态和反馈层，加入「生图连接」「工具模型」，移除顶部卡片。工作台直接打开「生图连接」，退出设置回工作台。扩展 `packages/services/src/image-generation/{contract,node,storage,validation}.ts`，支持多连接、多模型、协议、Base URL、路径、写入式 Key、默认／临时选型、分页及按需预览。v1→v2 在停止旧写入者后事务升级，保留任务、原图和发送记录。旧 Key 只迁入固定官方预设，持久标记防止清除后重新导入。沿用官方代理，按已评审规则为自定义目标实施 Host 侧 HTTPS 与目标校验，并显式反馈不可支持的代理路由。

   ```text
   Renderer 草稿与确认 → 本机 Host 校验连接、修订与请求 ID
                                       ↓
   Host 私有凭据 → 固定执行快照 → SQLite 幂等受理与跨窗单飞
                                       ↓
                            持久发送屏障 → 一次上游请求
                                       ↓
                            任务状态／原图 → UI 读取
   ```

   验证连接只做适配器支持的有界探测。试生成通过确认后复用正式受理。旧确认和冲突请求在发送前终止。发送后断连、超时或输出无法读取时保留结果未知状态并提示可能费用。读历史、保存设置及恢复任务均通过各自的本机接口。
4. **工具模型。** 使用本机专用设置保存现有文本 Registry 的模型引用。Git 在 `GitActionMenu.tsx`、`gitService.ts` 和 `gitCommitMessageGenerator.ts` 复用 `generateWorkspaceText`。Host 依可信 attachment、workspace identity、设置修订和实际供应商校验确认，空说明提交先回填可编辑草稿。自动标题经共享 `zcode-protocol` 把独立引用送入实际触发命令，`session-title.ts` 与 sidecar 共用解析规则。保留显式调用者和闲时票据优先级、手动标题与现有兜底。只有验证出可信本机桌面来源后才开放对应绑定。
5. **FrostFox。** 本地验收后阅读用户给出的 `/keys` 入口及生图文档，核对 API 地址、鉴权、模型、输出和费用，配置已证明支持的适配器。先验证连接，随后在已有凭据和明确费用授权时用中性样例试生成一次。Key 在设置界面输入。记录实际结果或具体接入阻塞。

## 验证

- 复用 `plugin-management-genimage-workspace.test.ts` 的隔离 profile、回环计数、冷重启和 PNG 字节比对。把原生场景放入桌面业务候选路径，并将历史插件兼容作为独立断言。运行 Desktop WDIO 定向用例，覆盖 BI01–BI08、BI10–BI11 的对应切片。网络和升级使用受控夹具，BI09 记录 FrostFox 实际结果。
- 扩展 Git 对话框用例与 CLI `off-peak-title.test.ts` 等定向回归。对照实际供应商请求、桌面／手机来源与旧确认零外发。按需要实测深浅主题、窄窗口、键盘焦点和可用平台窗控。
- 执行 `pnpm --filter @zcode/desktop typecheck:e2e`、`pnpm typecheck`、`pnpm lint`、变更范围架构检查及格式检查。复核新增和相关 React Hooks 诊断，对被忽略目录执行专项扫描。按实际运行产物填写覆盖矩阵，人工转正沿用独立的 E2E 审核流程。
